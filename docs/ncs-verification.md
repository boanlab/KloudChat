# NCS 수리 검산 보완

관련 구현: PR #143. 실제 출제·채점 품질은 이슈 #142에서 별도로 추적함.

## 원인과 변경

- 기존 모델이 수식 계산·선지 소거·채점을 모두 문장 생성으로 처리하여 서로 다른 답을
  같은 응답에 쓰는 문제가 있었음. 해당 문제의 정답을 프롬프트에 삽입하지 않음.
- `calculate`는 숫자·사칙연산·괄호만 허용하는 AST와 `Fraction`으로 계산함.
  코드 실행·파일·네트워크 접근은 없으며 길이·깊이·연산 결과 크기를 제한함.
- `check_ncs_answer`는 계산식·선지·명시적 반올림을 점검함. 제출 번호는 모델이 정하지
  않고 현재 사용자 메시지의 제한된 직접 제출 문법에서 확인함. 확인하지 못하면 채점하지 않음.
- 선지 입력은 문자열 배열·정수 배열·최대 10KiB의 JSON 배열 문자열만 정규화함.
  JSON 소수는 문자열 리터럴로 보존하며, 이미 실수로 변환된 배열·부울·중첩·임의 문장은
  거부함. 정규화 뒤에도 원래 산술 제한을 적용하고 입력 원문 없이 형식 오류를 안내함.
- 새 `NCS 수리 검산` Skill을 명시적으로 선택한 요청은 서버가 첫 검산 단계를 요구함.
  도구 미호출·오류·반복 종료 시 미검산 초안을 출력하거나 저장하지 않고 보류함.
- 조건 누락·계산상 복수 정답·정답 선지 없음은 추가 모델 설명 없이 고정 보류문으로 종료함.
  입력된 식이 틀릴 수도 있으므로 원래 문제 자체에 오류가 있다고 단정하지 않음.

## 적용 범위

- 일반 NCS 대화와 `NCS 조건·풀이 점검` Skill은 의사소통·문제해결 설명을 유지하며
  서버의 강제 수리 검산 대상이 아님. 일반 수리 대화의 도구 사용 지침은 최선 노력 방식임.
- 신규 NCS Agent에는 `문항 검산` 도구와 두 Skill을 연결함. Skill은 자동 활성화하지 않음.
- 기존 설치본의 사용자 편집과 도구 권한을 자동으로 덮어쓰거나 확대하지 않음.
  기존 사용자는 새 Skill을 설치하고 Agent에 허용한 뒤 `문항 검산` 도구를 켜야 할 수 있음.
- 도구를 끈 상태에서 수리 검산 Skill을 선택하면 기존 Skill 권한 검사에서 HTTP 422로
  거부됨. 모델 호출·Message 저장·크레딧 사용 전에 차단함.
- 제출 문법은 `2번`, `제 답은 1번입니다.`, `My answer is 4.` 등으로 제한함.
  모든 자연어 부정·인용·대화상 의도를 판별하는 의미 분석기가 아님.

## 보장하지 않는 사항

- 계산기는 **모델이 입력한 식의 산술**을 검증함. 원문에서 식을 세우는 과정, 단위 변환,
  누락 조건의 판별, `not_applicable` 분류 및 최종 자유문장 설명의 정확성은 보장하지 않음.
- 정상 검산 뒤에도 모델이 다른 계산값·오답 해설을 쓸 수 있음. 따라서 도구 호출 성공이나
  코드 테스트 통과를 전체 NCS 정답률·출제 품질 통과로 계산하지 않음.
- 연습 문제의 정답을 도구 진행 표시에는 노출하지 않지만, 모든 모델 응답의 의미적
  정답 선공개를 서버가 완전히 판별하는 구조는 아님.
- `local/qwen3.6-35b`는 당시 카탈로그에서 hybrid·strictLocal=false였음. 이름이나
  앱 크레딧 0만으로 실제 실행 위치 또는 제공자 무료 과금을 증명하지 않음.

## 검증 기록

- 2026-09-08, 입력 호환 보완 전 소스 `024392f`와 동일한 NCS 코드로 실제 Qwen 평가
  15개 사례·17개 대화 요청을 수행함. 독립 검토 결과 품질 통과 2, 문제 발견 2,
  안전 보류 11임. 보류 중 3개는 기대된 거부, 8개는 유효 요청을 완료하지 못한 경우임.
- 강제 검산을 선택하지 않은 가중평균 요청에서 계산 결과 80과 다른 최종 해설을 재확인함.
  일반 Skill 설명에는 별도의 경미한 과잉 일반화가 있었음. 두 finding을 닫지 않음.
- 저가 외부 모델 `qwen/qwen3.7-flash`의 첫 비교 2개에서도 선지 배열을 문자열로 보내
  검산이 실패함. 결과는 안전 보류였으며 정답 해결 성공으로 집계하지 않음.
- 선지 입력 호환 보완 `e9b399e` 후 두 모델에 원래 가중평균·오답 제출 요청을 각각
  새 세션에서 보냄. 최종 4개 요청 모두 계산 도구와 답변의 핵심 계산값이 80·25%로
  일치했으며, 두 오답 제출을 모두 오답으로 채점함. 앞선 15개 평가 전체를 재통과한
  결과나 통계적 정확도 개선율은 아님.
- 최종 비교의 Qwen 가중평균 답변에는 77.5를 단순 평균이라고 설명하는 모순과 JSON
  요청 미준수가 남음. 외부 모델의 가중평균 응답은 코드 블록 JSON과 요청하지 않은
  Artifact 1개를 생성함. 정답 계산 성공과 이 출력 품질 문제를 분리함.
- 외부 비교 두 차례의 앱 계정 크레딧 증가는 각각 115와 120이었음. 제공자 청구액이나
  실제 외부 completion 수를 의미하지 않음. 실제 요청·기록 모델은 선택 모델과 일치함.
- 최종 공개 브랜치 API 2,214 passed / 1 skipped, 별도 로컬 통합 API 2,276 passed /
  1 skipped 및 Ruff 검사를 통과함. 기존 경고 11개가 있으며 테스트 수는 정답률이 아님.
- 데스크톱 1440x900·모바일 390x844에서 새 Skill 노출·기본 미선택·선택/해제와
  가로 넘침·페이지 오류 0을 확인함. 기존 설치본을 권한 자동 확대 없이 명시적으로 설정한
  합성 QA 계정으로 검사했으며 자동 권한 마이그레이션 성공 사례가 아님.
- 현재 변경은 재발 방지 및 검산 경로 보완임. 이슈 #142의 전체 해결이나 학생 배포 승인이 아님.

## 병합 시 확인

- 같은 Agent 실행·도구 컨텍스트 경로를 변경하는 검색 자동화 PR #147과 병합 순서를
  조율해야 함. 검산 후 명시적 검색 지시를 전달하는 단위 회귀는 있으나, 두 PR을 함께
  병합한 전체 실제 검색 회귀를 수행한 것은 아님.
- 모바일 UI PR #144 병합 후에는 해당 표시 정책이 적용된 최신 main에서 재검증해야 함.
