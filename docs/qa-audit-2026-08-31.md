## Working Scenarios

### Undergraduate

- Start a report from a built-in template.
- Upload class material or a PDF.
- Generate a report, inspect sources, export to DOCX/HWPX.
- Reopen the work from history or artifacts the next day.

### Graduate student

- Create a project with standing instructions.
- Upload project knowledge files.
- Start a chat/report inside that project.
- Verify the answer uses project context and preserve version history.

### Office worker

- Upload a CSV or meeting note.
- Ask for extraction or summarisation.
- Convert the result into a document artifact.
- Export and share the output.

### Developer

- Ask for code or numeric verification in chat.
- Confirm tool-step visibility for `execute_code`.
- Save generated code as an artifact and reopen it from the side panel.

### Researcher

- Turn on web search or use project knowledge.
- Ask for evidence-backed output.
- Inspect sources and exported report quality.

### Sales / business

- Create an agent or design-backed pitch workflow.
- Generate slides and notes.
- Share the result and reopen it from artifacts.

## System Prompt Review Focus

- Date injection: chat/report/slides prompts are told the current date.

- Tool policy: responses should not claim tool execution without evidence.
- Search policy: web-search turns should verify factual claims via tool output, not memory.
- Korean-only rule: generated Korean prose should avoid Chinese-character leakage.

## Commercial-readiness remediation pass

- The deterministic detail audit now performs **19,631 rendered checks** over
  desktop, laptop, tablet and phone layouts and finishes with **0 observations
  / 0 unique defects**. It covers control names, tooltips, touch reachability,
  minimum tap areas, disabled-state explanations, overflow, empty-state next
  actions, page headings and artifact-panel expand/close/escape behavior.
- Fixed the issues found by that pass: persistent/touchable session menus,
  larger bulk-selection targets, a usable home “전체 보기” target, a semantic
  heading for a disabled AV surface, and width controls in gallery previews.
- Draft text is retained per work surface during SPA navigation; choosing a
  report template no longer consumes a partially written chat prompt.
- Artifact gallery tests now seed their own search and lazy-loading fixtures,
  instead of depending on whichever documents another test happened to leave.
- Restored downloadable blank Office forms for design templates. A chosen
  template can therefore be used outside KloudChat as well as generated into.
- Design extraction disables hidden reasoning for its short structured result;
  the prior configuration could spend the full output budget thinking and
  return an empty 422 response.
- Focused design/template/structured-document API regression: **371 passed**.
  Full API regression from this audit: **1,480 passed, 2 skipped**.
- Browser remediation set: **12 passed, 1 skipped** across gallery pagination,
  lazy loading, draft behavior, real design extraction, invalid-file handling,
  catalogue access, generated deck/document outputs, downloads and modal
  stability. The two model-backed document generations took 2.4 and 4.0
  minutes and completed successfully.

This is evidence of a materially stronger workflow baseline, not a claim of
feature parity with every competing commercial product. The remaining release
risk is chiefly operational: paid-model scenarios are mixed into the broad E2E
suite and can make a nominal “full run” take hours. They should be scheduled as
a separate nightly lane while deterministic UI/API gates run on every change.

### Evidence-to-export follow-up (2026-09-01)

- Found a submission-blocking mismatch: the report panel labelled its source
  shelf `APA`, but displayed unformatted metadata, offered no style choice and
  omitted the entire reference list from DOCX, PDF, HWPX and Markdown exports.
- Added APA, MLA, Chicago and IEEE reference formatting. The chosen style is
  stored as an artifact edit, reflected in print and applied to every report
  export; incomplete web results degrade cleanly when author or year is absent.
- Verification: 39 focused exporter tests passed, the Playwright style-change
  and persistence journey passed, and a live test-account DOCX was opened as an
  Office archive and confirmed to contain `참고문헌`, the source title and URL.
- Continued without a separate audit round: each source now reports the body
  sections that cite its `[n]` marker and jumps back to that section; unused
  sources and markers with no matching reference are called out explicitly.
- A reader can add a manually verified URL with author/publisher/year metadata
  and remove an unused candidate. Sources already cited in the body deliberately
  have no delete action. The six deterministic report-panel journeys pass.
- The shaped-document writer is now told the exact citation numbers available
  to it. The combined template/export API gate passed **397 tests**.
- Numeric evidence readiness now runs over every report section. Sentences with
  percentages, amounts, dates, counts or units but no same-sentence `[n]`
  marker are listed by section; unknown markers such as `[9]` are counted
  separately. Both jump back to the affected prose.
- The report toolbar and export menu expose the unresolved count before a file
  leaves the workspace, with an explicit `먼저 근거 확인` route. Its visible
  count is also in the button's accessible name. The six report-panel journeys
  remain green after deployment.
- The report now retains a reviewable research log: whether search was enabled
  and actually ran, every planned query, and selected/rejected result counts.
  It survives source and citation-style edits because it is stored with the
  artifact, and is shown above the source shelf. This exposes the existing
  planned-search/full-page-reading pipeline instead of duplicating the Deep
  Research MCP connector. The focused API gate passed **48 tests** and all
  **6 report-panel Playwright journeys** passed against the deployed build.
- Project knowledge is now a source shelf rather than an upload-only list.
  A user can retain a point-in-time web-page snapshot, inspect the extracted
  text and token footprint, and return to the live original. Uploaded files
  expose the same extraction preview. All **4 project-detail Playwright
  journeys** passed after deployment; a live test-account request stored
  `example.com` as a 55-token snapshot and the temporary project was removed.
- Project knowledge now enters generated reports as first-class evidence.
  Files and saved web snapshots that actually fit the turn receive citation

  listed as a source. The artifact research log separates web selections,
  project selections and context-budget exclusions, and the source panel links

  **393 API tests** and all **6 deployed report-panel journeys** passed.
- Large project shelves now use request-aware passage selection instead of
  spending the context budget on upload order. Small shelves remain whole to
  avoid false negatives from vocabulary mismatch. Files not selected are
