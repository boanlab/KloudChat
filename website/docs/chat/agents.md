# 에이전트와 스킬

에이전트는 역할, 지침, 도구, 자료를 미리 구성해 둔 도우미입니다. 영어회화 연습, 회의록 정리, 논문 검토처럼 자주 하는 일에 맞춰 직접 만들거나 동료가 공개한 것을 가져와 씁니다.

![에이전트 선택 메뉴](/img/guide/at-menu.png)

## 에이전트로 대화 시작

입력창의 **+** → **에이전트**, 에이전트 목록의 **실행** 중 어느 쪽을 선택해도 해당 에이전트와 새 대화가 시작됩니다.

- 대화 첫 화면에 에이전트의 **사용법**과 **시작 문장**(최대 6개)이 표시됩니다. 시작 문장을 누르면 그대로 전송됩니다.
- 에이전트 대화는 에이전트에 지정된 모델, 도구, 자료를 사용합니다. 자료가 등록되어 있으면 모델이 **자료 찾기** 도구로 검색합니다. 요청마다 자료 전체를 전달하지는 않습니다.
- 같은 프로젝트 안에서는 에이전트가 **노트 공유**로 남긴 결론을 다른 대화가 참조합니다.

기본으로 제공하는 에이전트는 **요약·정리**, **기록 정리**(회의·인터뷰·강의), **비교·결정**, **데이터 분석**입니다. **문서 작성**과 **발표 자료**는 평가를 통과하면 공개됩니다(그 전에는 관리자에게만 보입니다). 자기소개서·경력기술서와 고객 맞춤 제안서는 내려갔습니다. 목록과 스토어에서 사라지고 새 대화도 시작할 수 없지만, 그 에이전트로 하던 대화와 결과물은 그대로 열리고 내보낼 수 있습니다.

## 에이전트 만들기

**사용자 지정** → **에이전트** → **추가** → **에이전트 만들기**.

![에이전트 목록](/img/guide/agents.png)

1. **이름**, **한 줄 설명**, **지시**(이 에이전트가 늘 따를 역할과 규칙)를 적습니다. 화면마다 다른 지시는 `[채팅에서]`, `[보고서에서]`, `[슬라이드에서]` 한 줄 아래에 적으면 그 화면에서만 붙습니다(그 줄 앞의 내용은 모든 화면에 붙습니다).
2. **진행 과정**을 고릅니다.
   - **바로 답하기**: 요청을 받아 대화로 답합니다. 파일(DOCX·HWPX·PDF)은 만들지 않습니다. 파일로 받으려면 문서를 쓰는 **기본 과정에서 시작**을 고르세요. 설명이나 지시에 「파일」 「DOCX」 같은 말이 있으면 폼이 바꾸기 버튼을 보여 줍니다.
   - **기본 과정에서 시작**: 기본 에이전트(요약·정리, 기록 정리 등)가 일하는 순서를 그대로 따릅니다. 고르면 그 과정이 다섯 줄 이내로 보이고, 그 기본 에이전트가 쓰는 질문 카드·문서 형식·템플릿·검사가 그대로 붙습니다.
   - **직접 구성(고급)**: 질문·계산·검사·검토·다른 에이전트·내보내기를 한 단계씩 골라 순서를 짭니다. 맨 처음에는 「이 에이전트」 단계 하나가 들어 있습니다. 발표 자료에는 직접 구성이 없습니다.
3. **추가로 할 일**에서 **묶음**을 체크합니다(아래). 기본 과정을 고르면 그 기본 에이전트가 쓰는 묶음이 미리 체크되어 있어서, 그대로 두면 기본 에이전트와 똑같이 일합니다.
4. **결과물 모양**에서 **템플릿**(보고서·슬라이드의 구성)과 **테마**(색·글꼴·문체)를 고릅니다. **테마 관리**를 누르면 설정 › 테마로 갑니다. 보고서를 쓰는 에이전트는 **문서 형식**도 고를 수 있습니다.
5. **대화 시작**에 **사용법**과 **시작 문장**(최대 6개)을, **자료**에 파일이나 웹 주소를 넣습니다. 웹 주소는 등록 시점의 내용을 저장합니다.
6. **스킬과 도구**, **고급**(사용할 화면, 처음 여는 화면, 모델, 다양성, 색), **공유**를 정합니다. 공유는 **나만 쓰기** 또는 **모두에게 공개**이고, 공개할 때 **가져가서 편집할 수 있게** 와 **가져갈 수 있지만 내용은 비공개** 중 하나를 지정합니다.

활성화 토글로 일시적으로 사용을 중지할 수 있습니다. 삭제하면 자료와 색인, 그 에이전트의 직접 구성이 함께 삭제되며 기존 대화는 유지됩니다. 에이전트 상세의 개요에는 「이렇게 일합니다: …」 한 줄로 진행 과정이 보이고, **자세히 보기**로 체크한 묶음을 확인합니다.

## 묶음

묶음은 에이전트가 쓰기 전후에 하는 일을 몇 가지씩 묶은 것입니다. 에이전트 설정의 **추가로 할 일**에 묶음마다 체크 상자가 하나 있고, **자세히**를 누르면 그 안의 항목을 하나씩 켜고 끌 수 있습니다.

| 묶음 | 항목 |
|---|---|
| 쓰기 전에 준비하기 | 빠진 정보 먼저 묻기 · 날짜 미리 계산하기 · 금액·합계 미리 계산하기 |
| 다 쓴 뒤 검토하기 | 자료에 없는 내용이 없는지 근거 확인하기(수치는 도구 결과에서만 인정 · 직함·제품명까지 확인) · 형식 검사 · 어긋난 곳 고치고 다시 확인하기 |
| 마무리하기 | 상투적인 표현 걷어내기 · 다 쓰면 파일로 내보내기(DOCX·PDF·HWPX·MD 중 하나) |

- 보고서 화면에서는 날짜·금액 계산, 형식 검사, 고치고 다시 확인하기가 보고서를 쓰는 과정 안에서 늘 이루어지므로 「이 과정은 늘 합니다」로 표시됩니다. 대화 화면에는 형식 검사와 내보내기가 없습니다.
- 기본 에이전트도 같은 묶음으로 만들어져 있습니다. 예를 들어 기록 정리 = 쓰기 전에 준비하기 + 다 쓴 뒤 검토하기(할 일의 담당자·기한 확인 포함) + 마무리하기(내보내기 꺼짐)입니다.
- **내 묶음**: **사용자 지정** → **에이전트** → **추가** → **묶음 만들기**, 또는 직접 구성 화면의 **이 순서를 묶음으로 저장**으로 만듭니다. 만든 묶음은 내 모든 에이전트의 추가로 할 일에 체크 상자로 나옵니다. 묶음은 에이전트 탭의 **묶음** 줄(묶음 관리)에서 고치고 공유합니다.
- 공유는 스킬과 같습니다(나만 쓰기 · 모두에게 공개). 파일로 내보내거나, 다른 모델이 검토하거나, 다른 에이전트를 부르는 묶음과 직접 구성은 관리자가 **진행 과정 검토**에서 승인한 뒤에야 다른 사람에게 적용됩니다. 기본 과정과 기본 묶음만 쓰는 에이전트는 승인 없이 바로 공유됩니다.

## 세부 설정과 내 템플릿

보고서를 쓰는 에이전트는 진행 과정 아래 **세부 설정**(계산·검사·목차)에서 **이 에이전트에서 따로 정하기**를 켜면 템플릿이 정한 값에서 시작해 바꿀 수 있습니다. 끄면 템플릿(또는 문서 형식)의 설정을 그대로 씁니다.

- **쓰기 전에 계산**: 날짜 계산, 견적 합계, 투입 인력, 대안별 총비용, 필수 조건·가중 점수, 경력 기간 같은 기본 제공 계산을 고릅니다. **날짜 기준**(자료의 날짜 또는 회의한 날)도 정합니다.
- **쓰는 방식**: 웹 검색 안 함, 그림은 요청할 때만, 고정 목차.
- **구조 규칙**: 목차(순서), 필수 표(열 이름), 맨 위 핵심 요약 줄 수, 개조식 문체, 쪽수 제한. 코드가 확인합니다.
- **검토 규칙**: 말로 적은 규칙입니다. 다 쓴 뒤 판단 모델이 어긋나는 문장을 찾아 보여 주고 고치지는 않습니다.
- **계산 확인**, **판정 검사**, **서식 보정**, **빠진 것 채우기**: 기본 제공 확인과 보정 단계를 이름으로 붙입니다.

**결과물 모양** › 템플릿 아래 **새 템플릿**(또는 템플릿 고르기 창의 **새 템플릿**)에서 내 문서 템플릿을 만듭니다. **기본 템플릿에서 시작**을 고르면 그 템플릿의 모든 설정(문서 형식의 머리 항목·번호·머리 모양·개조식·「끝.」, 지침, 장르 규칙, 점검표, 빠진 정보 질문, 검사, 세부 설정)이 채워집니다. DOCX·HWPX 양식을 올리면 그 글을 쓰는 모델이 참고합니다. 모양은 테마의 색과 글꼴로 그립니다. **모두에게 공개**하면 다른 사람이 고를 수 있고, 편집은 만든 사람만 합니다. 만든 템플릿은 템플릿 고르기 창의 **내 템플릿**에 보입니다.

## 에이전트로 저장

잘된 대화를 에이전트로 남깁니다. 결과물 카드의 **⋯** 또는 보고서·슬라이드 패널의 **⋯**에서 **에이전트로 저장**을 누르면 에이전트 만들기 화면이 채워진 채로 열립니다. **저장**하기 전에는 아무것도 만들어지지 않습니다.

- **지시**에는 「이 대화에서 정한 것」(보고 대상, 분량, 꼭 넣을 것 등)이 들어갑니다. 내가 보낸 메시지만 읽어서, 그 대화가 쓰던 모델로 정리합니다. strict-local 대화는 strict-local 모델로만 정리하고 밖으로 보내지 않습니다.
- 대화의 템플릿·테마·스킬, 기본 과정과 묶음이 그대로 채워지고, 대화에 올린 파일은 **자료**에 함께 저장할지 고릅니다.
- 비공개로 공유된 에이전트의 지시는 옮겨지지 않습니다.

## 워크스페이스 스토어

**사용자 지정** → **에이전트**의 **탐색**에서 다른 사용자가 공개한 에이전트를 확인할 수 있습니다. **공식** 배지는 관리자가 공개한 항목입니다. **가져오기**를 누르면 **사본**이 내 목록에 생성됩니다.

- 사본에는 원작자의 지식 파일이 포함되지 않습니다. 진행 과정과 묶음은 함께 옵니다(승인을 기다리는 직접 구성은 빼고 기본 과정으로 옵니다).
- "내용은 비공개"로 공개된 에이전트의 사본은 편집할 수 없으며, 원본이 변경되면 사본에도 그대로 반영됩니다.
- 그 외의 사본은 독립적으로 관리되므로 원본이 변경되어도 영향을 받지 않습니다.

## 스킬

스킬은 **해당 요청에만** 적용하는 작업 방식입니다. 입력창의 **+** → **스킬**에서 최대 3개까지 선택하며, 전송하면 해제됩니다. 설치만 해서는 적용되지 않습니다. 인용 형식 맞추기, 계산·단위 검증, 비교표 만들기, 논문 구조, 한 장 요약 등이 제공됩니다.

![스킬 화면](/img/guide/skills.png)

- **사용자 지정** → **스킬**에서 설치와 사용 중지, 직접 만들기(이름, 설명, 사용 시점, 절차, 필수 도구, 공개 범위)를 수행합니다. 공개한 스킬은 스토어에 등록되며 다른 사용자는 사본으로 가져갑니다.
- **사용자 지정 › 스킬 › 추가 › 스킬 업로드**에서 SKILL.md(.md) 또는 SKILL.md가 든 .zip·.skill 파일을 여러 개 한 번에 올릴 수 있습니다. .md는 맨 앞 YAML 머리에 `name`과 `description`이 있어야 하고, `resources/`의 .md·.txt는 본문 끝 「참고 자료」에 붙습니다. 올리기 전에 파일마다 미리 보기와 보안 스캔 결과(막음·주의)를 보여 줍니다. 스크립트(.py, .sh, .js 등)는 저장하거나 실행하지 않고 제외합니다. 문장 검사는 휴리스틱이라 모든 위험을 찾지는 못합니다. **초안으로 올리기**를 고르면 꺼진 상태로 저장됩니다.
- 스킬 상세의 **⋯ → 내보내기 (SKILL.md)**로 내 스킬을 SKILL.md 파일로 받습니다. 키·토큰처럼 보이는 문자열이나 보이지 않는 방향 제어 문자가 있으면 공개(공유)가 거절됩니다.
- 도구가 필요한 스킬은 챗 화면에서, 도구 호출을 지원하는 모델을 사용하며, 해당 도구가 연결된 경우에만 활성화됩니다. 조건을 충족하지 못하면 사유가 표시됩니다.
- 프로젝트에 **추천 스킬**을 지정하면 해당 프로젝트의 입력창에서 우선 표시됩니다.
