# 파일 첨부

입력창의 **+** → **파일·사진 첨부**로 파일을 첨부하면 모델이 파일 내용을 근거로 답변합니다. 여러 파일을 한 번에 첨부할 수 있으며 끌어다 놓기와 붙여넣기를 지원합니다. 이미지와 오디오/동영상 화면에서는 첨부를 제공하지 않습니다.

![첨부 문서를 근거로 답변한 대화](/img/guide/chat-with-file.png)

## 첨부 가능한 형식

| 분류 | 형식 | 조건 |
|---|---|---|
| 문서 | PDF, Word(.docx), 한글(.hwp, .hwpx), PowerPoint(.pptx), Excel(.xlsx) | 스캔한 PDF는 관리자가 글자 읽기(OCR)를 연결한 경우 쪽마다 글자를 읽습니다. |
| 텍스트·코드 | .txt, .md, .csv, .tsv, .json 및 대부분의 코드 파일 | 텍스트로 읽습니다. |
| 이미지 | PNG, JPG, GIF, WebP, TIFF, BMP | 문서 사진은 글자 읽기(OCR)로 글자를 읽습니다. 그림 자체는 **4MB 이하**의 PNG·JPG·GIF·WebP만, 이미지 인식을 지원하는(목록의 👁) **strict-local** 모델에 전달됩니다. |
| 음성·영상 | mp3, wav, mp4 등 | **25MB 이하**이며 관리자가 음성 전사를 연결한 경우 문자로 변환해 읽습니다. |

파일 하나의 최대 크기는 200MB입니다. 구형 오피스 형식(.doc, .ppt, .xls)은 지원하지 않습니다. 읽지 못한 파일은 답변의 작업 단계에 **읽지 못한 첨부**로 표시됩니다.

## 첨부 파일의 참조 범위

첨부한 파일은 해당 대화의 이후 요청에서도 계속 참조됩니다. 작업 단계에 **이전 턴 첨부**로 표시됩니다.

- 파일 분량이 한 번에 처리할 수 있는 범위를 넘으면 **질문과 관련된 부분**을 선별해 전달합니다. "제7조의 내용을 알려 주세요"와 같이 요청하면 해당 조항 주변이 전달됩니다.
- 전달된 범위에 답이 없으면 모델이 **자료 찾기** 도구로 파일 내부를 검색합니다.
- 반영 정도는 작업 단계의 첨부 파일 항목에 반영, 잘림, 빠짐으로 표시됩니다.

보고서와 슬라이드 화면은 이전 요청의 첨부를 가져오지 않으므로, 문서 작성에 사용할 자료는 해당 요청에 직접 첨부해야 합니다. 다른 대화에 첨부한 파일도 저절로 참조되지는 않습니다. 이미 올린 파일은 **+** → **파일함에서 고르기**로 다시 붙이고, 여러 대화에서 늘 같은 자료를 쓰려면 [프로젝트](../personal/projects)에 등록하십시오. 관리자가 **내부 자료는 strict-local로만** 정책을 켠 환경에서는 첨부가 있는 요청을 같은 모델의 strict-local 판이 답합니다. ## 파일함

왼쪽 메뉴의 **파일함**에 계정의 파일이 모두 모입니다. 탭이 둘입니다.

- **올린 파일**: 대화·프로젝트에 첨부하거나 올린 파일
- **대화에서 만든 파일**: 코드 실행 결과(CSV 등), 이미지, 차트처럼 대화 중에 만들어진 파일

줄마다 크기, 올린 때, 어느 대화나 프로젝트의 파일인지가 보입니다. 이름으로 찾고, 내려받고, 하나씩 또는 골라서 지울 수 있습니다. 프로젝트 파일을 지우면 프로젝트에서도 빠집니다.

새 대화·보고서·슬라이드에서 같은 자료를 다시 쓰려면 입력창의 **+** → **파일함에서 고르기**에서 파일을 골라 붙입니다. 다시 올리지 않으므로 기다릴 필요가 없습니다.

대화를 지울 때는 **대화의 파일도 함께 지우기**를 고를 수 있습니다. 고르지 않으면 그 대화의 파일은 파일함에 남습니다. 프로젝트 파일은 대화를 지워도 지워지지 않습니다.

## 인식 정확도 향상 요령

- 찾으려는 내용을 구체적으로 지정하십시오. "이 파일을 요약해 주세요"보다 "이 파일에서 재택근무 신청 절차만 정리해 주세요"가 정확합니다.
- 표가 많은 자료는 PDF보다 Excel이나 CSV 형식으로 첨부해야 정확하게 인식됩니다.
- 첨부한 한글 파일(.hwpx)은 파일 칩의 **문서로 열기**를 누르면 편집 가능한 보고서로 바로 변환됩니다. 변환할 때 모델을 호출하지 않으므로 크레딧도 소모되지 않습니다.

## 스캔한 PDF와 문서 사진

관리자가 글자 읽기(OCR)를 연결했다면, 글자 층이 없는 PDF 쪽과 문서 사진은 올린 뒤 기관 안에서 글자를 읽습니다.

- 파일 칩과 프로젝트·에이전트 자료 목록에 **글자 읽는 중 3/10쪽**처럼 진행이 보입니다. 다 읽기 전에 질문하면 읽은 쪽까지만 근거로 쓰고, 읽지 않은 쪽은 알 수 없다고 답합니다.
- OCR 엔진이 먼저 읽고, 자신 없는 쪽과 표가 있는 쪽은 그림을 읽는 strict-local 모델이 다시 읽습니다. 쪽 그림은 이 두 곳 밖으로 나가지 않습니다.
- 두 결과가 글자나 숫자에서 다르면 **확인 필요 n쪽**으로 표시됩니다. 금액·날짜처럼 중요한 값은 원본과 대조하십시오.
- 글자가 거의 없는 사진은 글자를 읽지 않은 것으로 보고 그림으로만 다룹니다.
- 한 문서에서 읽는 쪽 수에는 관리자가 정한 상한이 있습니다. 넘으면 **앞 n쪽까지**로 표시됩니다.

## 이미지 첨부

이미지는 이미지 인식을 지원하는 strict-local 모델에만 전달됩니다. 개인정보 검사는 글자만 확인하므로 이미지는 기관 밖으로 나갈 수 있는 모델에 보내지 않습니다. 그 밖의 모델을 선택하면 파일은 첨부되지만 모델이 내용을 확인하지 못합니다. 이전 요청의 이미지는 다시 전송되지 않으므로, 같은 이미지에 대해 추가로 질문하려면 다시 첨부하십시오.
