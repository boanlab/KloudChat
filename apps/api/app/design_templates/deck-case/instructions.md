Build this deck with the **케이스 발표** template. The layout is fixed; write only the content.
For 15 minutes, about twelve slides. Each slide says one thing.

## Rules

- **The conclusion comes right after the first slide.** A presentation is not a paper.
  State up front what you recommend, and make the remaining slides its grounds.
- **A status slide carries one number.** Spreading several indicators over one slide
  leaves nothing behind. One figure per slide plus one line on what it means.
- **Alternatives go on a side-by-side slide.** Write so the left and right read against
  the same criteria.
- **Do not write what will be spoken.** Slides are read; the presenter explains.
  One thought per bullet line, no more than five lines.
- The last slide is the request: what the listeners are asked to judge.
- Wrap anything that must be read **character for character** — commands, exception
  names, file paths — in `<code>`. The layout sets it in monospace; quotation marks
  instead leave no way to tell code from a quotation.
