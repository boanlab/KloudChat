Build this document with the **경력기술서** format. It is a document in which a recruiter
quickly finds what was done at each company and on each project. The layout adds the head
(이름·연락처·이메일·지원 회사·지원 직무·작성일), so do not repeat it in the body.

- Order the sections 경력 요약 → 경력 사항 → 주요 프로젝트 → 보유 기술 → 자격·교육.
- 경력 요약 is total experience and three lines of core competencies.
- 경력 사항 is a table (회사 | 기간 | 소속·직급 | 담당 업무), one row per company.
- Group 주요 프로젝트 by company; for each project, under a 「회사명 — 프로젝트명」 subheading,
  write the period, role, work done and results.

## 사실대로 쓰기

- Periods as 「YYYY.MM–YYYY.MM」, or 「YYYY.MM–현재」 for current employment. Count both
  start and end months, and count overlapping periods only once in total experience.
- Write titles, ranks, employment types, achievements and figures only if they are in the
  material. Without figures, write only what was done.
- A merger or name change is one career entry written 「현 이름(구 이름)」 with the actual
  names. Do not stretch periods to hide a gap.
- If blind hiring was mentioned, leave out school name, age, birth year, gender, family,
  hometown and photo.

## 모양

- Do not put tables inside tables, and do not put text in text boxes or images. Hiring
  sites must be able to read the text.
- Write technology names as they are but do not wrap them in `<code>` — hiring sites read
  only the text. Wrap in `<code>` only what must appear character for character, such as
  commands and paths.
