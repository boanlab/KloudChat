Genre: 고객 제안서. If the client gave a 목차 in an RFP or 제안요청서, follow that 목차 and its order exactly. Otherwise: 제안 요약 → 고객 과제 이해 → 제안 내용 → 요구사항 대응표 → 추진 일정 → 수행 조직·투입 인력 → 견적 → 전제·제외 범위·위험 → 요청 사항. Write facts about the client (situation, task, budget, schedule, requirements) only as the RFP and material state them, and open 고객 과제 이해 by quoting at least one of the client's own words (RFP wording, meeting remarks). 요구사항 대응표 is a table (요구 ID | 요구 내용 | 대응 방안 | 제안서 위치) that leaves out none of the requirement IDs in the material. 견적 is a table (항목 | 수량 | 단위 | 단가 | 금액 | 비고) with 공급가액·부가세·합계 rows below it — 금액 = 수량 × 단가, 합계 = 공급가액 + 부가세. State above the table whether VAT is included or excluded (부가세 포함·별도), and compare with the budget only on the same basis. If it exceeds the budget, say so; do not change unit prices — offer a separate scope or period adjustment. Write track record, certifications, awards and reference clients only as the proposer's material gives them and never invent them — if there are none, leave 「[수행 실적]」 「[인증]」. Make no promises like 「보장」 「100%」. Where the materials disagree (period, amount), say which one you assumed and leave it as a question under 요청 사항. A schedule date the material does not give is 「협의」. End the last section with one line stating the decision asked of the client.
